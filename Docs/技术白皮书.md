# DPS v4.5 "Persona" 技术白皮书

本文件提供了 DPS (Dynamic Persona System) v4.5 的全面技术架构说明。该系统是一个基于 ZennoDroid 平台的、由 AI 驱动的人物画像行为模拟框架。

---

## 1. 项目概述

### 1.1 什么是 DPS v4.5？

DPS v4.5（代号：**Persona**）是一个**人物画像驱动的行为决策框架**。它不仅是简单的脚本执行器，而是一个模拟真实用户生命周期、心理状态和行为偏好的复杂系统。

该系统通过 100+ 个画像字段，结合深度学习（通过 AI 接口）和行为记忆，使每个设备（Device）都能演化出独特的用户人格。

### 1.2 解决的问题

| 问题 | DPS 解决方案 |
|------|-------------|
| **行为同质化** | 通过 AI 生成差异化画像，避免大量账号表现出相同的行为模式 |
| **生命周期管理** | 自动追踪用户的阶段演进（如：从备孕期到育儿期） |
| **静态行为模式** | 基于画像状态（如：今日心情、兴趣点）实时生成会话计划 |

### 1.3 目标平台

- **ZennoDroid 7.x+**：利用其 Android 模拟器自动化能力进行底层操作，DPS 负责高层决策

### 1.4 核心架构特性

- **动态编译**：代码以 `.cs` 文本形式存储，运行时动态编译执行，无需预编译 DLL
- **模块化设计**：逻辑高度解耦，核心功能（Core）、业务逻辑（Modules）与平台代码（ZDProjects）分离

### 2.2 动态编译机制 (ModuleLoader)

系统采用 `Microsoft.CSharp.CSharpCodeProvider` 进行运行时编译，**v4.5 新增编译缓存**：

```
┌─────────────────┐
│  ZD Own Code    │  1. 调用 RunModule()
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  检查缓存       │  2. 比对文件时间戳
└────────┬────────┘
         │
    ┌────┴────┐
    │ 缓存有效? │
    └────┬────┘
    是 ↙     ↘ 否
         │
         ▼
┌─────────────────┐
│  ModuleLoader   │  3. 读取 .cs 文件
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  合并 using     │  4. 提取所有 using 语句置于顶部
│  拼接代码体     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ CSharpCodeProvider │  5. 内存编译
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  缓存 MethodInfo │  6. 存入静态缓存
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  反射调用 Run() │  7. 执行并返回结果
└─────────────────┘
```

#### 编译缓存机制 (v4.5 新增)

| 组件 | 说明 |
|------|------|
| `_methodCache` | 缓存编译后的 MethodInfo |
| `_timestampCache` | 缓存文件时间戳 |
| `_cacheLock` | 线程安全锁 |

**缓存失效条件**：
- 模块文件 (.cs) 被修改
- 任何 Core/*.cs 依赖文件被修改

**性能提升**：
| 场景 | v4.0 | v4.5 |
|------|------|------|
| 首次运行 | ~500ms | ~500ms |
| 后续运行 | ~500ms | **<10ms** |

### 2.3 模块间数据流

模块间通过两种方式通信：

1. **ZD 变量**：作为各模块间的"总线"
   - `project_root` - 项目根目录
   - `device_id` - 设备标识
   - `persona_json` - 画像数据缓存
   - `session_plan_json` - 会话计划
   - `*_result` - 各模块执行结果

2. **JSON 文件**：持久化存储
   - 画像数据 → `Persons/{device_id}.json`
   - 会话记忆 → `Memory/{device_id}/{date}.json`
   - 运行统计 → `Stats/{device_id}_stats.json`

### 3.2 画像生命周期

系统定义了 7 个核心阶段，模拟用户从备孕到育儿的完整生命周期：

| 阶段码 | 名称 | 说明 | 典型时长 |
|--------|------|------|----------|
| TTC | 备孕期 | Trying To Conceive | 不定 |
| T1 | 孕早期 | 1-13 周 | 13 周 |
| T2 | 孕中期 | 14-27 周 | 14 周 |
| T3 | 孕晚期 | 28-40 周 | 12 周 |
| PP0 | 产后早期 | 0-3 个月 | 3 个月 |
| PP1 | 产后中期 | 4-12 个月 | 9 个月 |
| NP | 育儿期 | 1 岁+ | 持续 |

每个阶段拥有不同的参数：
- `sessions_per_day` - 每日会话频率
- `avg_session_minutes` - 平均会话时长
- `primary_concerns` - 主要关注点

### 3.3 会话模拟逻辑

`SessionRunner` 采用加权随机选择算法：

1. 从 `BehaviorConfig.json` 读取动作权重
2. 根据画像中的 `TypingSkillLevel` 计算打字速度
3. 执行加权随机选择动作序列
4. 记录每个动作到 Memory 文件

动作类型及默认权重：
- `browse` (浏览) - 50%
- `read_post` (阅读帖子) - 20%
- `like` (点赞) - 15%
- `comment` (评论) - 10%
- `post` (发帖) - 5%

## 7. C# 5.0 约束与规约

### 7.1 为什么是 C# 5.0？

`CSharpCodeProvider` 使用的编译器版本是 C# 5.0，比 ZD Own Code 直接编写的版本更旧。因此外部 `.cs` 文件必须严格遵守 C# 5.0 语法。

### 7.2 禁止使用的语法 (C# 6.0+)

| 语法 | 版本 | 替代方案 |
|------|------|----------|
| `$"Hello {name}"` | 6.0 | `"Hello " + name` 或 `string.Format()` |
| `obj?.Property` | 6.0 | `if (obj != null) obj.Property` |
| `nameof(MyClass)` | 6.0 | `"MyClass"` |
| `int.TryParse(s, out int x)` | 7.0 | 先声明 `int x;` 再调用 |
| `switch` 表达式 | 8.0 | 传统 `switch` 语句 |
| `??=` 空合并赋值 | 8.0 | `if (x == null) x = value;` |

### 7.3 模块规约

1. **入口方法**：所有模块必须包含静态 `Run(object projectObj)` 方法
2. **变量访问**：必须通过 `CoreHelper.GetVar/SetVar` 访问 ZD 变量
3. **路径处理**：使用 `CoreHelper.NormalizePath` 确保路径格式一致
4. **错误处理**：所有模块必须 try-catch 包裹，返回 `SUCCESS` 或 `ERROR: xxx`
5. **日志输出**：使用 `CoreHelper.Log/LogErr` 而非直接调用 `project.SendInfoToLog`

## 8. 部署指南

### 8.1 ZennoDroid 变量配置

在 ZD 项目中创建以下变量：

| 变量名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `project_root` | 文本 | ✓ | 项目根目录路径 |
| `device_id` | 文本 | ✓ | 设备唯一标识 |
| `force_regenerate` | 文本 | | 设为 `true` 强制重新生成 |
| `persona_json` | 文本 | | 画像数据缓存 |
| `ai_config_json` | 文本 | | AI 配置缓存 |
| `*_result` | 文本 | | 各模块执行结果 |

### 8.2 Own Code 配置

将 `ZDProjects/*_OwnCode.cs` 中的代码复制到对应的 ZD Own Code 动作块中。

### 8.3 首次运行

1. 设置 `project_root` 为项目目录
2. 设置 `device_id` 为设备标识
3. 运行 Initializer → 创建目录结构
4. 运行 Main → 自动触发 PersonaCreate 生成画像
5. 后续运行 Main → 正常执行会话流程
