# Persona Store tests

Unit and contract suites use synthetic closed-vocabulary trait values and evidence hashes. They verify independent per-Soul keyed commitments, defensive immutable snapshots, export request/cursor/payload/receipt seals, stable replay, retained-trait HMAC recomputation, fixed-time digest comparison, and exact 10,000-revision/16-MiB limits. The provider-owned revision corpus contains 27 complete raw wire payloads; the history-export corpus contains 17 complete raw wire payloads covering active retention, logical deletion, impossible tombstone order, nested Soul/device/account mismatches, time/version attacks, sensitive classification, exact keys, proof fields, and duplicate JSON. Both the .NET strict codec and the Python Draft 2020-12 Schema plus DPS ordering/history keywords must make the owner-declared decision for every case.

The required Integration suite uses exact PostgreSQL 18.4 from `DPS_TEST_POSTGRES`, creates disposable schemas and a distinct least-privilege Persona runtime role, and rejects the persistent GBrain Company port/database. It additionally verifies foreign-owned empty-schema rejection before DDL, per-column ACL drift, immutable export replay across restart/correction/deletion, denied raw receipt reads, and valid-vocabulary trait tamper detection. Missing PostgreSQL is `INFRA_ERROR/NOT_RUN`, never a mock pass.

These checks are not KMS/backup/WAL/cache deletion proof and are not GBrain, Windows, device, canary, or scale evidence. `KMS_CRYPTO_ERASURE_NOT_IMPLEMENTED` therefore remains a release blocker for final-erasure claims.
