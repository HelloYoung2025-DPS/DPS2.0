# Persona Store operations

The module is proposed. Shadow compares deterministic per-Soul keyed commitments. The kill switch stops writes; rollback restores the prior signed BOM without rewriting revision history. Export, correction, and deletion require the exact `soul_id` / `device_binding_id` / `platform_account_id` tuple.

Migrations run only with the exact migrator role. C# creates an absent schema without `IF NOT EXISTS`, binds its owner, and rejects pre-existing empty or foreign-owned schemas before migration. Runtime receives `USAGE`, bounded table reads excluding key/export-receipt material, and six fixed `SECURITY DEFINER` functions for key read, mutation/export receipt resolution, atomic mutation/export sealing, and dispatch acknowledgement. It has no raw table or column DML, sequence privilege, or schema creation. The export writer validates its request key against an immutable deployment-key digest, recomputes all keyed proofs, and binds every nested revision and retained payload to authoritative relational rows before inserting an append-only receipt. The catalog fingerprint includes `pg_attribute.attacl`; explicit runtime/PUBLIC column grants fail before DDL/DCL. Both PostgreSQL operations and Binding mutation-fence acquisition time out within five seconds.

`persona.revision/v1` is the deterministic DPS ledger truth. Its legacy-named `traits_sha256` field is a 64-hex HMAC-SHA-256 commitment under an independent random per-Soul key, not an enumerable raw digest. This module has no GBrain credential, network, source, page, embedding, similarity, or semantic-search operation. Ordinary rollback never rewrites committed history. A `deleted` revision means `LIVE_PRIMARY_LOGICAL_DELETED`: the transaction removed separately stored trait payload and key rows from the live PostgreSQL primary and recorded that limited scope. It does not prove removal from WAL, backups, replicas, caches, exports, GBrain/projectors, or any other downstream copy.

`KMS_CRYPTO_ERASURE_NOT_IMPLEMENTED` is a hard release blocker for any final-erasure or cryptographic-erasure claim. The current per-Soul key is a PostgreSQL row, not an externally managed KMS key, and the deletion audit intentionally leaves `external_destruction_receipt_sha256` null. Final erasure requires a future version with an external KMS destruction receipt tied to the exact Soul/key epoch plus retention/deletion evidence for WAL, backups, replicas, caches, exports, and downstream projections. Until then, UI, API, evidence, release notes, and operator reports must use only “live-primary logical deletion.”

`ExportHistoryV1Async` is the versioned, exact-Soul data export. In one Soul-serialized transaction it binds the request HMAC to the snapshot tail, HMAC cursor, canonical payload SHA-256, HMAC receipt, and immutable receipt ID. Identical replay returns the original sealed snapshot byte-semantically even after correction/deletion; a new idempotency key reads current truth. Every retained trait payload is re-HMACed before release. Raw retained traits make the receipt `privacy_class=sensitive`. Receipt rows are denied to raw runtime reads and are append-only, but they are still separately retained export copies: current logical deletion removes `trait_payloads` and `persona_hmac_keys`, not previously issued exports. V1 fails closed above 10,000 revisions or a 16-MiB complete wire payload.

The deployment-scoped request-HMAC key is a data-protection secret, not configuration text. It is injected outside Git and must remain stable for the lifetime of v1 idempotency receipts. Operators must not replace it in place: rotation requires an expand migration that stores a key identifier, dual-verifies old/new request commitments, soaks, and only then retires the old key. If the key is suspected compromised before that migration exists, enable `kill_persona_store_writes`, retain reads, and perform a human-approved rebuild rather than accepting false idempotency conflicts.

Production composition uses `PostgresPersonaStore.CreateTrusted` with Binding's signed composition attestation and public `IBindingMutationFenceClient` contract. Before database access, Persona verifies the pinned root, exact Release BOM and generation, Binding configuration/trust epoch, implementation/contracts/host artifact digests, validity window, and exact non-public sealed Binding fence-client identity. The migrator records that tuple; each mutation is rejected unless it matches the latest recorded composition. Persona production source references only Binding contracts; the Binding implementation owns active-revision resolution, revoke serialization, and the session lease. Persona retains that lease until its own commit or rollback completes. Persona Integration may compose the real Binding source from the test layer, but full inter-module PostgreSQL evidence still requires Binding's own Integration receipt and must not be inferred from Persona evidence alone.
