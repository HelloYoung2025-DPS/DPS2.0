# Control Plane Host migrations

`001_create_control_plane_truth.sql` establishes the module-owned PostgreSQL 18.4 runtime-truth boundary. Apply it only through `PostgresControlPlaneTruthMigrator` with a privileged migration DSN, a dedicated Control Plane database, and an already-created independent runtime login role. The migration revokes database `TEMP`/`CREATE` from public/runtime, and the runtime role receives only schema usage, `SELECT` on provider trust, runtime truth, receipts, quarantine and outbox, plus execution of the exact JSON helper and two fixed atomic write functions. It never receives direct table `INSERT`.

All five tables have update/delete and truncate triggers. Bootstrap creates a new schema exclusively and refuses every unmarked pre-existing schema; a concurrent creator causes rollback rather than adoption. PostgreSQL 18.4 supplies each named constraint's exact `pg_get_constraintdef` baseline, which is stored in its migration comment and never re-baselined on later runs. Runtime startup attests its exact session/current identity, timeout and trigger mode, a bidirectionally isolated `NOINHERIT` role graph, persistent non-RLS relation shape, all columns against the built-in `pg_catalog."C"` collation, exact constraint baselines, independent indexes, object ACLs, migration ownership, function body hashes/security modes, and all 13 trigger tuples before each operation. The migration owner remains a trusted boundary: a compromised owner can alter both an object and its baseline comment, so these checks prove runtime/accidental drift resistance, not owner compromise resistance. New migrations use expand-migrate-contract and must preserve the prior signed BOM's read compatibility. Never target port 55434 or the `dps_gbrain_company` database.
