# Control Plane Host tests

The 9 Unit and 23 Contract executions run without PostgreSQL against deterministic validation, hashing, parser, connection-policy, migration-source, receipt wire-codec, the policy-owned promotion and submission-lifecycle wire codecs, P-256 signer/state-verifier boundaries, and in-memory journal boundaries. They fail on zero tests, skips, partial execution, unknown producers/contracts, prepared memory, scope mismatch, idempotency conflict, malformed or token-like identifiers, non-canonical Base64/arrays/slugs/timestamps, unsafe connection defaults, or a migration that restores direct runtime inserts. Promotion tests prove exact snake_case round-trip and reject duplicate/additional/missing fields, uppercase or empty UUIDs, non-Zulu timestamps, trailing-newline IDs, malformed UTF-8, oversized payloads, and direct `action.proposal/v1` use as execution authority. The consumer differential test embeds provider-owned device, platform-account, binding, Persona, SoulMemory read-back, and GBrain Source-ID corpora directly from their canonical module paths, locks their exact case IDs, and applies the Control Plane parser to each provider expectation; provider fixtures are not copied into this module and raw numeric or duplicate-property payloads are not round-tripped through a loose object model. Separate promotion, lifecycle, and receipt object-level adversarial corpora are checked by their owner C# codecs and by the locked Python Draft 2020-12 validator with active format checking. Exact corpus ID sets are locked so deleting an adversarial case fails. Byte-level property order, whitespace, escaping, duplicate-key, and malformed UTF-8 canonicality are separately enforced by the codecs because JSON Schema validates parsed instances rather than raw bytes. Canonical-hash tests lock domain-separated business-key, receipt-payload, promotion, and lifecycle commitments, cover every envelope field, and prove a former delimiter-boundary collision no longer aliases two receipts.

The two required Contract gates are intentionally separate: the locked .NET gate executes exactly 23 contract cases, while `control-plane-host.contract-schema` executes exactly 16 isolated Python `unittest` cases against the receipt plus Policy-owned promotion, reconciliation, recovery, and submission-state Draft 2020-12 schemas and their shared schema/codec corpora. This keeps the trusted runner's restore-to-test command shape closed and makes a missing Python/schema dependency fail independently.

Lifecycle tests prove that reconciliation, recovery, and Policy-state authorities cannot collapse; typed capability absence or shared keys fail before a wire exists; the recovery approval capability must inspect the exact recovery DTO; signer output is checked against its declared public key; strict state decoding rejects duplicate fields; forged signatures and cross-Soul/BOM/idempotency replay fail; only PENDING/UNKNOWN may reconcile; and only an exact signed `RECONCILED_NOT_SUBMITTED` chain may produce a fresh bounded recovery attempt. Unit coverage rejects wrong Policy port auth scopes, reused credential-authority fingerprints, and authority/port timeouts above five seconds. It proves pre-cancelled work never invokes an authority, cancellation after signing never reaches a Policy port, a port ignoring cancellation still returns a fail-closed timeout, and a delayed uncooperative authority is quarantined without a second call or mid-use payload zeroing; its late signature and payload are discarded and zeroed. The coordinator Contract test exercises the real producer to role-specific proposed port facade to strict signed-state consumer path, while remaining Contract—not authenticated transport, PostgreSQL, or production evidence.

Six additional lifecycle Contract executions drive both outbound authorities through the production `ControlPlaneSubmissionLifecycleProducer` verification path. A capability that declares public key A but signs with private key B, returns malformed 64-byte P1363 material, returns a valid DER signature instead of P1363, returns the wrong length, completes only after the authority deadline, or replaces its signing key after composition must fail before the reconciliation or recovery Policy port is invoked. The late valid signature and retained canonical payload are also required to be discarded and zeroed.

The required `Integration` suite uses `REAL_POSTGRESQL` exact 18.4 from `DPS_TEST_POSTGRES`. The target must be a dedicated disposable Control Plane database because the migration removes public/runtime temporary-object creation. Every normal execution creates an independent schema and a distinct login-capable least-privilege runtime role; the migration credential is never reused by runtime. Its exact floor of 56 executions covers all five full raw provider v1 JSON shapes, canonical NIST P-256 signatures, active BOM/key/trust and exact committed replay after revocation, atomic truth/receipt/outbox commit, conflict quarantine, concurrent duplicate delivery, four database crash windows, cancellation rollback, exact Soul/device/account isolation (including a colliding 112-bit truncated GBrain Source address), parser boundaries, GBrain signed checksum proof, direct-write/DDL denial, and catalog/constraint/trigger/function/index/ACL/column tamper rejection. It explicitly rejects unmarked pre-existing schema adoption, constraint-parenthesis changes, a `STRICT` atomic-function mutation, role inheritance or either membership direction, column-level insert grants, shadow collations, and any sixth table/view/partition/sequence/foreign relation. Port 55434 and the `dps_gbrain_company` database are rejected. Missing PostgreSQL is a required `INFRA_ERROR`/`NOT_RUN`, never `SKIP` or a simulated pass.

No suite in this module is Windows, ZennoDroid, device, canary, or scale evidence.
