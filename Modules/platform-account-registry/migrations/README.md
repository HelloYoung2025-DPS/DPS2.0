# Platform Account Registry migrations

`001_create_platform_account_registry.sql` creates the module-owned PostgreSQL 18.4 schema. `002_add_binding_reservations.sql` is the idempotent expand migration for empty pre-reservation schemas. `003_require_signed_authorization_evidence.sql` adds the alias-key epoch, exact canonical identifier constraints, and immutable signed-evidence document/hash proof. `004_add_release_generation_fence.sql` persists the highest accepted active Release BOM generation. `005_harden_platform_length.sql` makes the database enforce the same 64-character platform limit as the C# and JSON contracts. `006_require_lowercase_authority_metadata.sql` aligns stored alias-key and authorization-evidence identifiers with the authority-owned lowercase contract and refuses legacy mixed-case rows. The application executes embedded SQL migrations in lexical order. It stores only alias digests, key metadata, and public signed evidence, never raw email addresses, phone numbers, platform login identifiers, credentials, private keys, or service secrets. Within the migration, `accounts` is created before provider-owned `binding_reservations` so its foreign key is valid.

Migration 003 deliberately refuses to fabricate evidence for pre-release rows. A non-empty older schema must be exported and re-authorized by the external signer, or retired under an approved maintenance plan, before this migration can pass.

Every embedded migration is recorded with its source SHA-256 in `module_schema_migrations`; changing an already applied migration stops startup. Initialization also rejects a lower Release BOM generation or a different BOM at the same generation. Rollback therefore deploys the previous compatible artifact only under a newly signed, higher generation.

Account state, append-only authorization revisions, idempotency receipts, and the immutable outbox are committed in one transaction. Identity and alias fields cannot be mutated in place. Future persistence changes must follow expand-migrate-contract; other modules use versioned queries or events instead of table access.
