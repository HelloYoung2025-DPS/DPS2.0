# Operation Compiler contracts

Consumes `approval.decision/v1` and uniquely owns `operation.compiled/v1`. Steps are an explicit allowlist. Adding an action or step is a public behavior change requiring compatibility, security, shadow, and canary review.

The proposed, not-yet-released v1 contract contains exactly one step. Multi-step operations require a separately reviewed compatible protocol instead of silently widening v1. Public DTOs bind explicit snake_case JSON names, reject missing required or unknown JSON members, carry the canonical `approval_sha256`, and recompute both `operation_id` and `step_id` from the shared canonical implementation during validation. Transport code must use `OperationCompiledV1Json`, which also rejects duplicate JSON properties, and consumers must retain the deep-frozen value returned by `ValidateAndSnapshot()`.

`operation.compiled.v1.canonical.json` is the machine-readable approval-digest, operation-ID, and step-ID specification with golden vectors. Its SHA-256 is bound from the Manifest-registered schema, so a canonical-spec change must update the schema and enter the public-contract impact path. Schema/DTO mapping tests bind public JSON names. A change to that file, the schema, DTO JSON mapping, or canonical behavior invalidates existing instruction receipts and requires `command-orchestrator` consumer rebinding before another write or release decision. The new required approval digest means the current consumer must rebind and adapt before merge-head verification.

Canonical IDs prove deterministic identity only. They do not authenticate the approval source or authorize a side effect. The compiler no longer accepts a naked approval DTO: it asynchronously requires `IAuthoritativeApprovalReader` to return an `ACTIVE` snapshot matching the exact request scope and two independently supplied digest values. The module-owned boundary passes cancellation to both ports, mechanically caps the complete read/compile/handoff path at the Manifest-declared 2000ms, and requires a durable quarantine adapter for every late terminal outcome. R3 release remains blocked until a production adapter backs the reader with authenticated policy-approval receipt truth and the downstream consumer verifies producer provenance.
