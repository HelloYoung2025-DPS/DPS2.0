# Consumed contracts

- `approval.decision/v1`, owned by `policy-approval`.

The compiler never compiles a caller-supplied approval record. It uses the lookup request only to query asynchronous `IAuthoritativeApprovalReader.ReadAsync`, passes boundary cancellation, then snapshots the returned record and enforces exact `approval_id`, proposal, Soul/device/account, trace, idempotency, `ACTIVE` status, and canonical SHA-256 equality before compilation. A reader that returns after cancellation cannot continue into command handoff; its terminal outcome is quarantined by `OperationCompilationBoundary`. The compiler also enforces consumed v1 constraints that the provider DTO alone does not prove: exact schema syntax, opaque-ID patterns, string bounds, unique policy IDs and denial reasons, policy-ID pattern, policy-version syntax, platform-authorization length, and parameter semantics. `duration_ms` is the Planner-aligned canonical decimal form of `1..600000`; `selector_ref` and `value_ref` use the same 128-character opaque-reference grammar and reject prompt/coordinate shapes. Stricter local denial-of-service ceilings apply before or during enumeration: 16 parameters, 32 evaluated policy IDs, 32 denial reasons, 64-character parameter/policy identifiers, and non-backtracking regular expressions. Provider validation still owns the cross-field approval semantics.

The local Integration harness signs the provider-owned strict `approval.decision/v1` wire and exact lookup/state metadata with a disposable P-256 key, then verifies a pinned public key before returning through `IAuthoritativeApprovalReader`. That signature frame is test infrastructure, not a second public approval contract and not evidence that `policy-approval` produced it. A production adapter must consume policy-owned authenticated truth without exposing policy implementation types or tables.
