# Operation Compiler operations

Only exact allowlisted actions compile. Unknown steps and coordinate fallback fail closed. Disable `operation_compiler_v1` with `kill_operation_compiler` and restore the previous signed BOM; never claim an external side effect was rolled back.

Do not route R3 traffic on the basis of `Validate()`, `approval_sha256`, `operation_id`, or `step_id` alone: canonical hashes are not signatures. There is intentionally no naked-approval compile API. Production eligibility requires a real `IAuthoritativeApprovalReader` adapter backed by authenticated `policy-approval` receipt truth with the declared timeout, downstream producer authentication, use of the strict duplicate-rejecting JSON codec at transport boundaries, and retention of the deep-frozen value returned by `ValidateAndSnapshot()`.

`OperationCompilationBoundary` is the only module-owned command handoff path. It runs asynchronous authoritative read, allowlisted compile, strict `operation.compiled/v1` serialization/re-entry, and asynchronous command accept under one fixed 2000ms production deadline. Both ports receive the same linked cancellation token. `ICompiledOperationCommandConsumer` receives read-only memory that stays valid until its task reaches a terminal state and must copy any retained value before completing; the producer then zeroes its buffer.

A caller never receives an accepted operation after the deadline. `IOperationBoundaryQuarantine` is mandatory, receives the exact non-sensitive scope, phase, operation/wire commitments when available, trigger, and late terminal state, and must durably isolate the outcome with its own bounded write policy. Hosts call `DrainLateQuarantinesAsync` during graceful shutdown; any quarantine write failure is a failed release condition. A consumer exception or late completion is never a successful handoff claim.

The local Integration suite exercises a real P-256 signature, pinned verification, strict public wires, a disk-flushed pending file followed by an atomic rename, replay quarantine, and reconstructed restart. Those files and keys are disposable test fixtures only, and the suite does not claim a filesystem directory-fsync or real process-kill proof. It does not replace the policy PostgreSQL gate, a policy-owned production receipt adapter, signed Release BOM approval, Windows/ZennoDroid gates, or device evidence.
