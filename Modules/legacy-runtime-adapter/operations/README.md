# legacy-runtime-adapter operations

The module is transitional and not independently release eligible. Runtime routing may change only through an exact signed Release BOM.

F5 P0 containment is now explicit: all seven production wrappers, including the actual `Initializer_OwnCode.cs` and `Main_OwnCode.cs` dispatch path, return the dedicated `ERROR_BRIDGE_REQUIRED` token before reading `project_root`, source files, configuration, or ordinary project variables that could disable the gate. Each wrapper cleanup variable is written in its own exception boundary, so a missing optional Zenno variable cannot skip later cleanup or the final error token. SessionRunner writes the same failure token before and after cleanup and treats logging as best-effort, so a logging exception cannot preserve stale `DONE`. The wrappers and all five public `SessionRunner` entrypoints clear command payloads, action/success telemetry, legacy-success flags, queues, proposals, and memory projection variables. They never write `DONE`, so the documented Zenno switch falls through its default route to `BadEnd`, not `GoodEnd`. Writable `zd_step_plan` input is rejected, Vision cannot reinterpret an error as success, legacy retry/recovery is proposal-only, and unverified results cannot create interaction or spoken-memory facts. Result tokens are not trimmed or split: `SmartOrchestrator` permits only raw exact `SUCCESS`, followed by a declared expected page and an exact observed-page match; missing or `unknown` postconditions fail. The dedicated `ZDProjects/TestRunner.cs` and `ZDProjects/RuntimeTestRunner.cs` remain the only homes for legacy test DSL behavior.

Rollout order is synthetic test, shadow, bounded canary, rolling waves, and soak. Shadow is forbidden from producing real-world side effects. The feature flag, kill switch, canary rule, rollback target, minimum evidence, and human approval boundary are machine truth in ../module.yaml.

The immediate kill switch is the compile-time wrapper constant `LEGACY_DISABLE_NEW_COMMANDS=true`; no ordinary project variable can turn it off. Rollback keeps that gate active and may route only to a previously verified safe signed BOM; it must never restore the unsafe pre-containment SessionRunner execution path. Rollback must not pretend that external side effects or destructive data changes were reversed; those require stop, reconcile, compensate, or restore procedures.

The SessionRunner strangler baseline is under `strangler/`. Its verifier freezes exactly 79 tracked legacy C# byte streams against baseline commit `cac7ccbcce927a1a3a62cfd376497f0d30cc47e4`. The original approval set remains closed at four paths: three F1 test-truth repairs and the SessionRunner F5 P0 repair. Eight later containment repairs—all seven production wrappers and `SmartOrchestrator`—are recorded as a separate closed set, never as an extension of the original four. Case-insensitive `.cs` discovery, component collision detection, and case-aliased legacy-root/`Modules`-child rejection prevent `.CS` and alias-path injection. Symlinked or reparse-like entries are rejected even when a linked directory hides the only C# file. Any other content, BOM, encoding, line-ending, symlink, deletion, collision, alias, or new legacy-scope C# path fails closed.

The verifier cannot approve itself. `PASS` requires `DPS_LEGACY_BASELINE_ANCHOR` to name an external, read-only provider record whose file and parent are controlled by an identity different from the verifier and are not writable by it. The provider ID, issuer, audience, UTC issue time, complete-record digest, Git commit/tree/parents, 79-entry inventory digest, exact 4+8 repairs, explicit repair policy, verifier, schemas, baseline data, module rules, all required test source hashes, and minimum test-method counts are bound together. Required commands use `.venv/bin/python` at CPython 3.12.13; the independent trusted runner must construct that environment and preserve the interpreter SHA-256, exact argv, environment, raw output, and exit status in its evidence. A missing provider returns `WAITING_EXTERNAL` with a non-zero exit. A candidate-created repository file, same-identity chmod-only file, mutable manifest, weakened verifier, deleted tests, fixed-success command, or PATH-selected interpreter cannot satisfy this gate. Passing the gate is static characterization only; it is not compilation, Windows, ZennoDroid, ADB, GBrain, integration, device, canary, or release-approval evidence.

Before any command execution can be re-enabled, an independently reviewed bridge must expose a fixed ABI and accept only an exact signed Release BOM. It must reject variable project roots, peer/extension globs, first-exported-type reflection, reparse points, UNC paths, and extra files, and bind `soul_id`, `device_binding_id`, `platform_account_id`, command and trace IDs, policy approval, action lease, idempotency key, native result, and deterministic postcondition. Windows/ZennoDroid and authorized non-production-device gates remain `NOT_RUN`.
