# Audit Metrics migrations

`001_create_audit_metrics.sql` is an additive, idempotent PostgreSQL 18.4 migration. It creates module-owned `audit_events`, digest-only `audit_quarantine`, and revision-ordered `audit_relay_trust_states`; exact-scope ordering/indexes; a unique scoped idempotency key; JSON/column checks; and database triggers that reject every update, delete, or truncate. Every trust-state insert also takes the exclusive form of the same transaction advisory lock held in shared mode by an audit append, making highest-revision validation and the business commit one serialized unit. The highest immutable trust-state revision is the only current candidate and still requires root-signature verification in the service. `002_configure_audit_runtime_role.sql` revokes public/runtime schema, table, and function defaults, grants the independent runtime login select/insert only on business tables, select only on trust state, and execution only of the immutable JSON constraint helper required by inserts.

Create an independent unprivileged runtime login first, then apply both migrations with the separate privileged `PostgresAuditMetricsMigrator`; do not grant the migrator membership in the runtime role or reuse its credential with `SET ROLE`. Append each new root-signed active/revoked trust state with the privileged release path. The runtime `PostgresAuditMetrics` API verifies its exact login identity and cannot perform DDL or rewrite trust history. Do not point tests or migrations at the GBrain Company database. A local source build or in-memory test is deliberately not `INTEGRATION_VERIFIED`; the required Integration suite must execute against the dedicated `DPS_TEST_POSTGRES` PostgreSQL 18.4 target.
