# Audit Metrics operations

`kill_audit_metrics_ingest` stops new ingestion without deleting historical audit. Rollback restores the previous signed BOM routing and preserves immutable events. Never use identity IDs as metric labels or treat aggregate counts as execution evidence.

The runtime writer must authenticate with an independent login credential whose `session_user` and `current_user` are the same unprivileged role; migration ownership stays with a separate operator credential. `SET ROLE` from an owner session is forbidden because `RESET ROLE` would restore owner rights. Every runtime connection attests login, superuser/DDL flags, role memberships, database ownership, and schema ownership before use.

The PostgreSQL implementation requires NIST P-256, an explicitly encoded signature, and the current root-signed Release BOM/key state before opening its append transaction. Current state is the highest immutable revision in `audit_relay_trust_states`; the runtime may only read it, while the signed-state reader also rejects in-process revision rollback or same-revision rewrite. Authorization time comes from the injected service `TimeProvider`, never from the caller. Trust-state inserts automatically take an exclusive transaction advisory lock; audit transactions take its shared form, then read and verify the highest revision on that same connection and transaction while holding the lock through commit. A rotation that wins the lock is therefore visible before any later audit write, and an in-flight audit that wins first is serialized before the rotation. The transaction has five-second database lock and statement timeouts, then either inserts one immutable event, returns an exact duplicate as a no-op, or appends only digest metadata to `audit_quarantine`. Invalid signatures, expired authorization, revoked keys, or inactive BOMs write neither business table.

Rollout requires the exact signed BOM/public-key binding, PostgreSQL 18.4 migration completion, shadow count comparison, and a bounded human-approved canary. The migrator role must own DDL; the runtime login must be denied `ALTER`, `DROP`, `TRUNCATE`, trigger control, role membership, and database/schema ownership before production evidence can pass. A higher signed trust revision rotates or revokes a BOM/key without reconstructing the service; older revisions remain immutable history and cannot become current. On rollback, stop routing new receipts and restore the prior writer; do not update, delete, truncate, or rewrite module tables. Scoped event and quarantine reads always require all three opaque IDs. Quarantine stores only event IDs and hashes, not raw PII, receipt bodies, or signatures.
