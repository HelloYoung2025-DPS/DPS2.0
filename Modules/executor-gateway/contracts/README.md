# Executor Gateway contracts

Consumes Command Orchestrator's dispatch, execution-authorization, and receipt protocol. Uniquely owns active `native.result/v1` and `native.submission.ack/v1`, plus deprecated `native.stop.proof/v1` in `quarantine-only` mode. Native must independently report command ID, lease ID, attempt, complete Soul/device/account/trace/idempotency scope, active-BOM digest and generation, execution-token digest, and the ordered step. Gateway-filled identity scope is forbidden. A native acknowledgement proves only durable submission; native success still requires the independently reported result and verified business postcondition.

`native.stop.proof/v1` must not be emitted by Executor, Worker, Policy Approval, or any runtime composition. Its existing schema, DTO, strict codec, historical verifier source, and contract project are byte-frozen by `provided/native.stop.proof.v1.freeze.json`. The historical verifier source is excluded from the production Executor assembly and linked only into the contract-test assembly to preserve byte/behavior evidence. The owner corpus at `provided/native.stop.proof.v1.corpus.json` and `LegacyNativeStopProofV1QuarantineClassifier` allow only bounded strict decoding and non-sensitive quarantine metadata. They do not expose the DTO, raw wire, signature result, evidence digest, or any domain authorization. Replay remains quarantine; malformed UTF-8, oversize input, duplicate/unknown fields, identity-shaped values, unknown major, and non-canonical versions are rejected. A future recovery authority requires a new Policy-owned major and cannot reinterpret v1.

The proposed, unreleased v1 dispatch and native-result contracts each require exactly one ordered step. This aligns JSON Schema with the existing C# behavior. Multi-step execution requires a separately versioned compatible protocol; Executor Gateway never sorts steps by ID.
