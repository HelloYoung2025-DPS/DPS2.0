# Executor Gateway tests

Unit/Contract active-BOM readers, approval-fence/lifecycle providers, native executors, postcondition verifiers, clocks, and fail-stop authorities are labelled fakes. They prove boundary logic only: fixed-format P-256 authorization and signed receipts, gateway-owned trusted time, exact command/lease/attempt/scope binding, 256-bit active-BOM token and generation binding, strict native acknowledgement attacks, pre-native policy-owned `SUBMISSION_PENDING`, `Inserted` plus `MaySubmit=true` enforcement, policy-owned `SUBMISSION_ACKNOWLEDGED` before lease release, and false-success prevention. They also prove that the native capability is inert and requestless before PENDING; a local timeout cannot abandon the policy guard; every uncertain first-byte path retains PENDING and roots the policy lease, native attempt, and late task until process death; provider injection and guardian-transfer uncertainty fail-stop; and concurrent existing PENDING/historical UNKNOWN states cannot dispatch or retry.

The deprecated `native.stop.proof/v1` contract is tested only as byte-frozen quarantine input. Freeze-manifest tests bind the exact Schema, DTO, codec, historical verifier source, contract project, classifier, and corpus hashes. The historical verifier source is excluded from the production assembly and linked only into the test assembly. The corpus attacks duplicate/unknown fields, malformed UTF-8, oversize input, attempt zero, identity-shaped data, unknown major, non-canonical version, and replay. Reflection tests ensure the production runtime assembly, constructors, interfaces, fields, methods, and properties expose no legacy proof authority. Historical codec/verifier tests preserve frozen behavior but cannot satisfy a runtime, UNKNOWN, guard-release, retry, success, Windows, or device gate. `required-security-tests.v2.json` lists non-deletable security IDs with their exact expected Category; its inventory test and suite floor fail closed together.

The separate required Integration suite launches the checked-in native fixture as an actual child process and is labelled `REAL_LOCAL_PROCESS`. The parent creates an inert process-bound attempt, flushes the complete submit request, and the child writes state with write-through plus `Flush(true)` before it may emit the acknowledgement; result retrieval uses the independent completion phase. Crash paths kill and reap the fixture process while durable PENDING remains blocking. A separate file-backed local authority fixture persists the lifecycle markers. The suite covers crashes before child submission-state flush and after flush but before acknowledgement, then constructs a fresh provider and proves both restarts return `WAITING_EXTERNAL` and reject the same attempt before another `SubmitFirstByteAsync`. It also proves ACKNOWLEDGED attempts cannot be blindly resubmitted, compares the child's independent submitted-request hash with the production implementation, and covers scope rejection and BOM switching.

The local authority fixture is not a deployed Policy Approval service, does not use PostgreSQL, and does not verify a real owner signature. Its files are test-only blocking markers, not public lifecycle contracts or production evidence. Both required-test inventories bind every ID to its exact suite `Category`; retaining a `[Fact]` under the wrong category is a gate failure. The suite must not be relabelled as PostgreSQL, Windows, ZennoDroid, ADB, or device evidence. Neither suite can issue `WINDOWS_VERIFIED` or `DEVICE_VERIFIED` evidence.
