# Executor Gateway operations

Activate only under an exact signed BOM and authenticated dispatch scope. Production composition must fix the real authorization verifier, verified BOM reader, cryptographically verified Policy Approval submission-lifecycle adapter, receipt signer, native executor, process-rooted guardian, postcondition verifier, trusted clock, and timeout at construction; none may be supplied per call. There is no runtime native-stop-proof verifier. Executor creates `CreateInertSubmissionAttempt()` before PENDING; that requestless capability may allocate only an isolated worker/handle and cannot cross the device boundary. The adapter acquires `approval.execution.fence/v1`, verifies owner signatures and authoritative read-back, and owns one combined PENDING/callback/terminal sequence. Only owner disposition `Inserted` with `MaySubmit=true` invokes `SubmitFirstByteAsync`; exact existing PENDING or historical UNKNOWN invokes no callback. The same PostgreSQL session guard remains held through the callback and durable acknowledgement, or is transferred to the process-rooted guardian on uncertainty.

A synchronous throw, null, timeout, cold Task, process death, or forged acknowledgement after PENDING may have crossed the side-effect boundary. Executor never converts these conditions to `UNKNOWN_SUBMISSION`; it transfers the exact lease/session, native attempt, and outstanding task to the process-rooted guardian, leaves durable PENDING unchanged, and emits only non-retryable `UNKNOWN_OUTCOME/WAITING_EXTERNAL`. Existing PENDING and historical UNKNOWN also return `WAITING_EXTERNAL` without callback or native dispatch. `native.stop.proof/v1` is byte-frozen quarantine input only and cannot unlock any state. If the provider fails after possible PENDING, injects an UNKNOWN callback result, or guardian transfer throws/returns invalid evidence, the constructor-fixed host authority must terminate Executor and all non-orphanable workers; no signed receipt may be emitted. ACKNOWLEDGED, historical UNKNOWN, and PENDING all block same-attempt resubmission.

The configured verified reader must cryptographically authenticate a supervisor-issued opaque 256-bit execution token and monotonic generation for the exact device binding; missing, stale, unknown-version, rollback, or mismatch stops execution. The native transport consumes that exact token and independently reports the full sent scope. Gateway uses only its injected trusted clock and rereads generation after native execution and before success. Expiry, reader failure, or generation/BOM change after a possible side effect produces non-retryable `UNKNOWN_OUTCOME`. `kill_executor_gateway` stops new native calls. Rollback changes future routing only; external side effects need compensation. The module remains proposed and non-release-eligible until the Policy/Executor lifecycle composition, real process-rooted guardian and fail-stop path, PostgreSQL race behavior, Windows transport, and device gates pass; deprecated v1 proof support is not a release milestone.
