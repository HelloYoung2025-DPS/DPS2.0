# Binding tests

Unit and Contract suites are deterministic and fail closed on zero tests, skips, partial execution, scope mismatch, duplicate conflict, and unknown versions.

The required Integration suite uses exact PostgreSQL 18.4 through `DPS_TEST_POSTGRES`. It also requires `DPS_TEST_PLATFORM_AUTHORITY_PKCS8_FILE` to point to an independently supplied DER PKCS#8 P-256 test signer whose public key matches the compiled platform-authorization root pin. The file is read only by the test process, its path and bytes are never logged, and the key is never generated, copied, or committed by this repository. A missing or mismatched signer is `INFRA_ERROR`, not a synthetic approval fallback. Every test creates independent random schemas for binding, device-registry, and platform-account-registry. Provider state is seeded and read only through provider-owned public contract clients; the suite never reads their tables or fabricates unsigned approval proof. It covers concurrent uniqueness, exact idempotent replay, pending-conflict quarantine before provider reads, scoped digest-only conflict quarantine, append-only revisions, revocation/no resurrection, retired/suspended/revoked provider truth, autonomous pending-attempt startup recovery, partial-reservation compensation, provider mutation freeze, revoke crash/retry release, repeatable commit-spanning mutation fences, canonical database identifier constraints, canonical outbox checksums, and cross-Soul isolation. Port 55434 and database `dps_gbrain_company` are rejected because they are reserved for persistent GBrain Company data.

Missing or inaccessible PostgreSQL or signer infrastructure is a required-test failure/`INFRA_ERROR`, never `SKIP`. These checks are not Windows, ZennoDroid, device, canary, or scale evidence.
