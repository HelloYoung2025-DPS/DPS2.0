# Consumed contracts

`device.registered/v1` and `platform.account.authorized/v1` are consumed as complete provider-owned current-state contracts. `device.binding.reservation/v1` and `platform.account.binding.reservation/v1` then freeze those exact revisions through held, active, and released provider-owned states. A caller cannot put any provider DTO into a binding command. Binding requests carry only canonical identifiers; the module queries both providers and requires the exact same Soul, binding, account, and device scope with `registered` plus `authorized` lifecycle status.

Production composition obtains `IDeviceBindingReservationClient` and `IPlatformAccountBindingReservationClient` from each provider-owned factory and passes those versioned contract clients to `PostgresBindingRegistry.CreateForCompositionAsync`. Each client exposes only its non-secret instance-configuration digest and trust epoch in addition to the versioned operations; the signed composition attestation binds both values. Binding source references only the provider contract packs: it has no provider source project reference, cross-module friend assembly, request-built proof DTO, or cross-module SQL. Integration tests may reference provider source to compose the real clients across independent schemas.
