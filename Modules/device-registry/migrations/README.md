# Device Registry migrations

`001_create_device_registry.sql` creates the PostgreSQL 18.4 persistence boundary for devices, provider-owned binding reservations, append-only capability revisions, idempotency receipts, an outbox, and idempotency-conflict quarantine. `002_add_binding_reservations.sql` is the idempotent expand migration for empty pre-reservation schemas. `003_require_keyed_fingerprint_contract.sql` converges only empty pre-release unkeyed schemas and enforces the exact v1 identifier, capability, and keyed-fingerprint constraints. The application validates a safe schema identifier and executes all embedded SQL migrations in lexical order. Within the migration, `devices` is created before `binding_reservations` so its foreign key is valid.

Only HMAC-SHA-256 fingerprint digests plus their non-secret canonical key ID and positive key epoch are persisted. Raw hardware identifiers, the HMAC secret, unkeyed fingerprint digests, and personal alias values are not accepted or stored. A populated schema containing the former `fingerprint_sha256` column cannot be cryptographically upgraded from that digest, so migration raises an error and requires independently approved device re-attestation; it never fabricates HMAC provenance. Every device mutation writes its current row, revision, receipt, and outbox record in one transaction. A repeated idempotency key with the same semantic command hash is a no-op; a different hash is durably quarantined and rejected.

Future changes use expand-migrate-contract. No other module may read these tables directly.
