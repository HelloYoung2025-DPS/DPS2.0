# Device Registry tests

The executable harness exits non-zero on any failed assertion. Unit and contract categories run without external services. They cover exact DTO versions, unknown and missing JSON fields, canonical envelope IDs, strict numeric JSON tokens, configured fingerprint key ID/epoch, secret-free provider-configuration digest and positive trust-epoch binding, ASCII capability syntax, declared and observed enumeration bounds, and deterministic reservation receipts. The required Integration category uses the real `DPS_TEST_POSTGRES` PostgreSQL 18.4 server, creates one random schema per test, and cleans it up after execution; missing infrastructure is a failure, never a skip. Port `55434` and database `dps_gbrain_company` are rejected before any connection because they are reserved for persistent GBrain Company data.

Integration coverage proves transaction rollback at every register crash window, update and retirement recovery, same-hash no-op, different-hash quarantine, keyed-fingerprint uniqueness, inactive key-version rejection, populated unkeyed-schema migration rejection, restart read-back, scoped Soul/binding/account isolation, provider-owned reservation persistence across restart, exact-revision mutation freeze and release, and absence of raw-hardware/PII/unkeyed-fingerprint columns. It is not Windows, ADB, ZennoDroid, canary, or real-device evidence. Required non-`PASS` outcomes fail release.
