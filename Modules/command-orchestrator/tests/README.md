# Command Orchestrator tests

The in-memory orchestrator is an internal deterministic test model, not a product entry point; product hosts must use the durable PostgreSQL implementation with independent Policy Approval signature verification and the database process capability. Deterministic tests cover duplicate/conflict delivery, authoritative `approval_sha256` propagation and tamper rejection, domain-separated canonical digest boundaries, former delimiter-collision vectors, complete operation/receipt field binding, nullable presence, ordered steps and canonical argument maps, strict UTF-8 rejection of isolated surrogate input, lease timeout, the post-dispatch crash window, out-of-order receipts, unknown outcomes, role/scope attacks, unknown protocol versions, and the versioned execution-authorization domain/encoding/algorithm/signature-format/generation/token contract. The Schema-bound machine canonical specification is verified against fixed bytes, hashes, public key, and signature. The separate Draft 2020-12 schema suite recursively covers all four public Schemas and proves that every SHA-256 field, schema version, timestamp, and P-256 P1363 Base64 signature rejects trailing bytes and noncanonical shapes; `contentEncoding` is never treated as an assertion. `required-security-tests.v1.json` lists non-deletable security test IDs; its inventory test and the exact suite count fail closed together.

The required `command-orchestrator.postgresql18` suite contains exactly 21 real-PostgreSQL tests; no environment-only probe is counted in that floor. `DPS_TEST_POSTGRES` is a mandatory exact-18.4 bootstrap-admin DSN, not the database under test. For every test the harness creates unpredictable restricted migrator/runtime login roles and a new dedicated database, then proves the exact database owner, a nonce-derived marker unavailable to pre-existing databases, and a live session-held advisory guard before the product migration may run. Teardown force-drops that database and both roles even when setup or a test is cancelled. Missing create/destroy authority, a forged marker, a lost guard, an owner mismatch, missing infrastructure, or unsafe reuse is `NOT_RUN`/`INFRA_ERROR`, never a passing or skipped test.

The suite proves database-clock-only lease acquisition, binding, dispatch validity and recovery; exact object/default ACL allowlists; complete identity-sequence parameters and ownership; state projection that cannot regress when an identity sequence is made descending; migration/catalog attestation; API-only runtime access; the independent 256-bit process capability; rejection of raw credential-only forged dispatch/receipt calls; command-owned authorization construction followed by the versioned Policy Approval P-256 signer port and local verification; append-only storage; duplicate/conflict semantics; single-winner leasing; crash recovery before and after dispatch; signed receipt/outbox atomicity; bounded retry; late reconciliation; cross-Soul/device/account isolation; restart durability; and fail-closed catalog/migration drift. Until all 21 tests run and pass against the dedicated PostgreSQL 18.4 database, this module must not claim `INTEGRATION_VERIFIED`.
