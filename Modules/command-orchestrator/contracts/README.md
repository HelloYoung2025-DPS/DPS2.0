# Command Orchestrator contracts

The module consumes `operation.compiled/v1` and uniquely owns `command.dispatch/v1`, `execution.authorization/v1`, and `command.receipt/v1`. Command Orchestrator constructs and remains the wire producer of `execution.authorization/v1`; Policy Approval is the independent P-256 signer reached through the versioned signer port and must not rewrite the producer field or any canonical payload byte. The executor consumes the command and authorization contracts and emits a receipt conforming to this owner-controlled protocol; this avoids a compile-time contract-ownership cycle.

The initial, not-yet-released v1 command protocol is exactly one ordered step. It carries the required authoritative `approval_sha256` from `operation.compiled/v1`; dispatch validation, command canonical bytes, and execution authorization all bind that value. The JSON Schema matches the C# producer and consumer invariant; multi-step operations require a separately versioned compatible protocol rather than sorting steps by ID.

`execution.authorization/v1` fixes the command-digest domain and encoding plus the ECDSA P-256/SHA-256, IEEE P1363, Base64 signature format. It binds the exact BOM digest, monotonic active generation, and SHA-256 of the supervisor-issued opaque execution token; the raw token is never part of this contract. Human guidance is in `provided/execution.authorization.v1.canonical.md`; the Schema-bound machine specification and cross-language bytes/digest/signature vector are in `provided/execution.authorization.v1.canonical.json`. Signed values are authorization evidence only; Executor Gateway must compare them with independently verified activation truth.
