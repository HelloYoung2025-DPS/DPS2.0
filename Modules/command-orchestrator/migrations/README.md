# Command Orchestrator migrations

`001_create_command_orchestrator.sql` is the proposed PostgreSQL 18.4 baseline. It creates append-only command, lease, attempt-event, signed-receipt, outbox, quarantine, migration-ledger, and catalog-attestation records. Command state is projected from immutable attempt events using attempt and explicit transition order rather than trusting identity-sequence direction; no state row is rewritten. Lease, binding, dispatch validity, and recovery timestamps come from the database clock after the per-command lock. Startup attestation covers the exact object inventory and ACL allowlist plus every identity sequence's type, start, increment, min/max, cache, cycle, identity mode and owned-by dependency.

The migrator owns the schema, tables, sequences, triggers, and `SECURITY DEFINER` functions. The runtime login receives only schema `USAGE` and `EXECUTE` on the exact versioned API inventory. It receives no direct table, column, sequence, DDL, ownership, inheritance, or PUBLIC-derived privilege. Each runtime API verifies a separate 256-bit process capability before reading or mutating module data; only its SHA-256 is stored in the append-only migration ledger. Startup binds the embedded migration SHA-256, capability SHA-256, exact PostgreSQL version `180004`, roles, owners, ACLs, function bodies/configuration, tables, columns, constraints, indexes, and append-only triggers into a catalog attestation. Any drift fails before runtime work.

Migration changes must be additive and receive a new immutable ledger entry; never rewrite this baseline or disable its append-only triggers in production. The required 21-test real PostgreSQL suite must pass before `INTEGRATION_VERIFIED` can be claimed.
