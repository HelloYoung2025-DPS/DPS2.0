# Operations

Run in an isolated, module-owned POSIX output directory with declared inputs only. The runtime requires descriptor-relative `openat` support, `O_NOFOLLOW`, directory descriptors, file and directory `fsync`, and advisory output locking as available on the supported macOS/Linux service hosts. Repository and output path components must not be symbolic links; a path identity change aborts the build.

The hard resource envelope is 256 MiB per artifact/source file, 1 MiB per module manifest, 10,000 source files, 1 GiB total source bytes, 32 MiB of Git tree listing, and 64 MiB per generated JSON document. Raising a limit requires a reviewed capacity and denial-of-service analysis. A killed writer may leave only the deterministic hidden temporary name or a two-link fully written final; the next locked retry removes the temporary link and revalidates the final bytes before accepting it.

Compare the source digest before and after publication. The builder emits `UNSIGNED_AWAITING_EXTERNAL_SIGNER`; an external controlled signer validates and signs the later Release BOM. Files are staged, file-synced, linked without replacement, directory-synced, made non-writable, and re-read before return. These local controls do not provide WORM retention against an administrator or output-directory owner; production retention and deletion protection remain blocked on an external immutable artifact store policy. Shadow builds are never published. Rollback retains content-addressed artifacts and changes only BOM routing.

Before opening any output, validate the complete signed `merge.decision/v1` object, not only its signature. Its Soul, device, account, trace, integration commit, policy digest, approval outcome, and timestamp must bind to the build request, and the request cannot predate the decision. The requested module version must equal the version in the workspace Manifest after that Manifest is matched to the signed Git tree. A mismatch is a rejected build, never a corrected or normalized request.

Before publishing the first output byte, claim `build_id` through `factory_artifact.claim_build_identity(...)` in PostgreSQL 18.4. The claim binds canonical request and verified-decision digests plus artifact, source tree, module/version, and integration commit. The database commit must complete before publication. A lost acknowledgement fails the attempt; an exact retry is safe, while the same ID with any different bound value is rejected. Never substitute the in-memory unit registry in a service composition.

Apply migration `001_build_identity_claims.sql` only with a dedicated migration identity to a dedicated empty database. Use a different non-inheriting runtime login, grant it only `USAGE` on `factory_artifact` and `EXECUTE` on the nine-argument claim function, and grant no table, sequence, schema-create, or DDL privilege. Required integration evidence uses distinct admin/runtime URLs and exact PostgreSQL 18.4. Missing URLs, equal identities, a pre-existing schema, unavailable PostgreSQL, or unavailable locked driver is `INFRA_ERROR`, never a skip or local fallback.

The production registry rechecks this runtime boundary on every connection before calling the claim function: exact server version, `NOINHERIT`, no memberships, no superuser/role/database/replication/bypass-RLS flags, no direct table privilege, no schema CREATE, and exact claim-function EXECUTE. Supplying a migrator or administrator connection is a rejected build, not a convenience fallback.
