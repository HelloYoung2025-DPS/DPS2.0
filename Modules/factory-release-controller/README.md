# Factory Release Controller

Status: proposed. The module has repository-level executable tests but is not yet production-release eligible.

The Release Controller advances the fail-closed rollout state machine and persists each accepted transition through the Factory Evidence Ledger before changing in-memory state. Its only active runtime input is `rollout.command/v2` from `factory-control-plane-host`, and its runtime output is `rollout.event/v2`; it does not consume raw `upgrade.intent` contracts.

Each v2 command carries one to 64 canonical receipt references and no caller-supplied risk tier. Receipt kinds come from an explicit allowlist; references are never normalized, and repeated separators, case ambiguity, raw-intent masquerades, and extra `:` components fail closed. Strict wire decoding rejects duplicate JSON members and non-finite values. Upgrade IDs, real canonical UTC seconds, opaque IDs, booleans, and exact nonnegative integer counts are checked by runtime code as well as the v2 schemas. A process-bound trusted resolver must return the exact ordered references, a non-zero receipt-set digest, the trusted risk tier, approvals, verification facts, candidate digests, side-effect count, and kill-switch state. Any disagreement is rejected before a ledger write.

Recovery requires an independently authenticated `factory-evidence-ledger` stream-head anchor. Recomputing every payload and event hash can make tampered replay bytes locally self-consistent, so the local hash chain is only an integrity-consistency check, not authenticity or authorization. The repository contains a private post-authentication semantic replay verifier, but it does not contain the production external anchor/currentness provider. Consequently the public `ReleaseController.recover` entrypoint unconditionally returns `WAITING_EXTERNAL`; it accepts neither a resolver callback nor an anchor DTO. A locally forged matching head therefore cannot activate recovery. The module remains `releaseEligible=false` until a separately reviewed fixed provider authenticates the head before calling the private semantic verifier.

The original v1 command and event schemas remain byte-frozen with machine-checked SHA-256 values. They are deprecated quarantine-only shapes with no runtime communication route. A fully valid v1 object can be classified for quarantine but can never advance or replay state.

The Release Controller is also the unique owner/producer of `release.bom.native.stop.authority.trust/v1`. This active proposed receipt binds the exact Release BOM and generation to the public Worker native-stop, Supervisor route-assignment, and Policy challenge authority sets sent to `factory-control-plane-host`. It contains public-key hashes, authority digests, validity metadata, and a signature only—never raw private keys, secrets, or activation tokens. Unknown majors and any producer, digest, signature, revocation, generation, or authority-set mismatch fail closed. Host activation remains blocked until the separately owned reciprocal consumer edge is present and exact.

The module remains fail-closed for unknown contracts, producers, states, receipt kinds, raw-intent masquerades, any v1 runtime attempt, digest drift, R4 work, self-approval, shadow side effects, and unarmed rollout kill switches. Host-side reciprocal v2 wiring is a separate change owned by `factory-control-plane-host`.
