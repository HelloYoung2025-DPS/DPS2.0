# Operations

The resolver is proposed and read-only. The feature flag is `factory_instruction_resolver_v2`; `factory_disable_instruction_binding` rejects new bindings. The Worktree Manager must hold the one-writer freeze while the resolver reads; the resolver also computes both object hashes from the same bytes and performs two final bound-file and full-diff checks. Any race aborts binding.

Runtime accepts only canonical `upgrade.intent/v2` bytes sealed as `VerifiedUpgradeIntentV2` by the fixed composition-root `UpgradeIntentTrustAuthority`. The Resolver does not accept plain dictionaries or a per-call verifier/time. The process-bound verifier binds the exact raw hash, full-intent hash, Intake peer, audience, trust receipt, nonce, verification time, and auth/Manifest/approval expiry; every expiry must be strictly later than trusted resolution time. `requested_target_modules` plus `authorized_write_paths` are the write authority. The larger `scope` only binds instructions and impact tests.

An existing trust receipt never bypasses verification: every cache reuse first rechecks the full attestation and then compares all verified fields with the cached capability. Receipt currentness validation first applies the locked Draft 2020-12 v2 Schema, strict JSON types, and the canonical receipt-ID hash. Unknown majors, non-BOUND inputs, invalid shapes, and failures that prevent current truth from being recomputed return no fabricated STALE object. When current truth is available and differs, the emitted Schema-valid STALE record preserves the exact prior receipt ID and source authority bindings.

`resolve` returns `VerifiedInstructionReceiptV2`, issued by a private authority owned by that Resolver instance. Use `canonical_receipt()` only to serialize the public contract; never feed that bare dictionary back into `validate`. Currentness validation requires the exact issued capability and binds its canonical bytes, full hash, receipt ID, producer/major, issuer/audience, issued/expiry time, nonce, generation, and status. Cross-Resolver capabilities, direct construction, same ID with different bytes, or any post-issuance mutation fail closed. Valid STALE output is also an issued capability.

All receipt timestamps are additionally parsed using Python's deterministic UTC calendar parser; Schema `pattern` remains a wire constraint but optional `format` packages are not trusted for calendar truth. `occurred_at`, `resolved_at`, and Intake verification time must agree; trust/auth/Manifest/approval expiry must be strictly later. The Intake nonce cache, Intake capability fingerprints, and receipt capability fingerprints are capped at 4096 active entries and pruned at their earliest trusted expiry. Quota exhaustion rejects new work; expired entries cannot be replayed.

The included HMAC verifier and receipt capability authority prove local process-bound integration and adversarial tests only. A portable cross-process signature or authenticated mTLS/DB receipt provider is still `WAITING_EXTERNAL`; until that provider and downstream v2 consumers exist the module remains proposed and release-ineligible. v1 is quarantine-only and has no communication route. Rollback routes to the previous signed Factory BOM within five minutes and treats receipts produced after the cutover point as stale. An instruction receipt proves bound scope and baseline facts only. Changeset truth requires an independent `changeset.contract-verification/v1` after `CHANGESET_FROZEN`; no receipt is production or release evidence by itself.
