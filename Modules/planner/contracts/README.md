# Planner contracts

`provided/` owns both majors of `action.proposal`. Version 2 is the only current Planner output. Its Draft 2020-12 schema and strict C# codec share one adversarial corpus and require typed digest references with exact forms `selector_[a-f0-9]{64}`, `value_[a-f0-9]{64}`, and `evidence_[a-f0-9]{64}`. This structural rule rejects prompt text, whitespace-free prompt tokens, Unicode/confusable text, PII, wrong reference types, and non-canonical digests without a keyword blacklist. Version 1 retains its original schema, DTO, codec, and corpus unchanged as deprecated shadow/quarantine read compatibility only; Planner must never produce it and downstream Policy must never promote it. Both majors are proposals only and carry no approval, lease, or execution authority. `consumed/` records public contracts owned elsewhere; this slice consumes none.

The JSON Schema proves structural shape. A conforming v2 boundary must additionally enforce the `x-dps-proposal-id` semantic derivation with `ActionProposalV2Json` or an equivalent registered Draft 2020-12 keyword validator. A stock validator ignores extension keywords and therefore cannot, by itself, prove that a syntactically valid UUIDv8 was derived from the declared Soul, device, account, and idempotency scope. The identity derivation domain remains `dps.planner.proposal-id/v1` across the compatibility window so the same scoped idempotency input retains one proposal identity; the v2 canonical commitment separately binds `action.proposal/v2` and the v2 domain. Exact central major modes are locked in the Manifest and mirrored by `tests/action-proposal-major-modes.v1.json`: v1 is `quarantine-only`, v2 is `active`, and unknown, missing-major, unknown-mode, or missing-mode inputs reject.
