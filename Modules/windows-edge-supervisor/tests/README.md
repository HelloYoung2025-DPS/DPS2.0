- `unit` (12 methods): artifact digest/capability validation, strict `db_` identity, stable routing, simulation-only state staging, active-drain-only directive preparation, concurrent retry reuse of one exact signed wire, checksum-chained durable state with an exclusive writer lease, same-store Resume/write serialization, one-use preparation-token ABA rejection, recovery when prepare/commit/abort rejects or applies then throws, exact third-state rejection, restart fail-closed behavior, protected rollback slots, independent Worker/Journal drain proof binding, proof-pair persistence, exact rollback, append-only evidence-chain tamper rejection, parent-path replacement and link rejection, same-size runtime rewrite and unsigned runtime member rejection, digest-bound fixed host configuration, and the launch-ABI block before process or runtime-channel invocation. Synthetic tests do not prove Windows Job Object behavior, immutable directory ACLs, handle-sharing semantics, or filesystem metadata durability under real power loss.
- `contract` (13 methods): the .NET suite covers production codecs, directive and receipt public-pack goldens, expiry-equality rejection, new-intake freshness versus signed durable continuation, fresh Journal proof for stale Worker continuation, deterministic Journal request binding, five-second provider timeout, pairwise-disjoint drain trust keys, the 19-field worker request hash, strict signed capability evidence with an independent log root, externally bound Windows-gate configuration, exact Zenno exchange decoding, canonical Journal payload bytes, independent Worker/Journal proof authentication, and the SPKI/PKCS#1 Zenno directive golden. Its module-local floor is fixed to the complete method count; the central candidate policy must be reconciled separately before release.
- `contract-schema` (7 Python methods): an independent required suite validates the owned Schemas, 64 owner-corpus cases, three worker-exchange wire fixtures, the signed drain-directive and Worker-only receipt wires, exact RSA-PSS parameters, false Windows claims, real signature fields, independent evidence-log proof fields, and the nine-case Zenno-owned exchange corpus. Exact owner-compatible UTC/version syntax, security digests, key IDs, canonical Base64, strict opaque IDs, null arrays/elements, and Int32 boundaries fail closed.
- `Integration` (2 methods): one hundred A/B cutover and rollback cycles plus explicit capability simulation. Output keeps `EvidenceKind=SIMULATION`; it cannot satisfy Windows or device gates.
- `windows`: external gate only. It requires Windows, PowerShell, the exact ZennoDroid installation, ADB authorization, signed A/B workers, PID/start-time/connection continuity evidence, one hundred real switches, and a 24-hour soak.

If any Windows prerequisite is missing, the gate exits non-zero and reports `WAITING_EXTERNAL`. It never converts absence, SKIP, or PARTIAL into PASS.

The audit is not disabled in the required wrapper.
