## Production loopback host

The shipped Zenno bridge already fixes `http://127.0.0.1:28741/dps/edge/v1/exchange`, a 15-second timeout, a 64 KiB response ceiling, Windows default credentials, and the `edge.bridge.exchange/v1` request. Start the Supervisor with `--host --config <absolute-path>` only on Windows. The config must exactly match `windows-host.config.example.json` and the externally protected `DPS_EDGE_HOST_CONFIG_SHA256`, `DPS_EDGE_HOST_ID`, `DPS_EDGE_RELEASE_BOM_SHA256`, `DPS_EDGE_PROTECTED_POLICY_SHA256`, and `DPS_EDGE_SERVER_KEY_ID` process values.

The host binds only the fixed loopback endpoint through `HttpListener` with Negotiate authentication and an exact SID allowlist. It loads one currently valid RSA certificate from `LocalMachine/My`, pins both its certificate thumbprint and SPKI-derived key ID, and signs every response with `RSA_PKCS1_SHA256`. A valid `POLL` is the handshake/health check and returns only a signed `WAIT`. `NATIVE_RESULT` returns 503 until a live Worker result channel is composed; no ACK, success, or retry permission is invented. Unknown majors, exchange kinds, actions, steps, properties, identities, body sizes, timeouts, or non-loopback clients fail closed.

The host keeps a single-writer evidence file open with replacement denied on Windows. Each flushed JSONL line binds sequence, timestamp, event kind, payload digest, previous head, and current head. Real capability evidence must bind at least 100 entries plus the independent log head and open-file identity. The evidence statement's own digest is not accepted as a substitute for this log root.

## Worker process containment

`FixedWindowsWorkerProcessController` contains the protected future launch path, but currently rejects every launch before `CreateProcess` because the cross-module Worker launch/runtime ABI is not frozen. It never substitutes a zero-argument launch for the Worker's actual required parameters and never accepts caller- or model-supplied arguments. When that ABI is separately versioned, the prepared path accepts only a one-use Supervisor authorization for an absolute `.exe` inside an approved version directory. A signed runtime manifest must cover the executable, DLLs, `.deps.json`, `.runtimeconfig.json`, configuration, health and shadow evidence, and every other runtime file; missing, extra, case-colliding or rewritten files fail. Windows holds read handles that deny write/delete for the full process lifetime and requires an immutable provisioning-only directory security descriptor. The future launch path then suspends the exact process, assigns it to a `KILL_ON_JOB_CLOSE` Job Object, revalidates the locked closure, and only then resumes it. `UnavailableWorkerRuntimeChannel` remains the production default.

## Explicit release blockers

This module is `proposed`, `releaseEligible=false`, and produces no production candidate stage or route transition. The following gaps are intentionally fail-closed and are not satisfied by simulation:

- The exact Worker launch arguments, local IPC, authentication and health/drain runtime ABI are not frozen. Capability assessment therefore always includes `worker-launch-runtime-abi-unavailable` and returns `WAITING_EXTERNAL`.
- Bootstrap validates signed files but does not prove that its active slot is a live, healthy process. Resume rejects persisted in-flight work and has no Journal-backed reconciliation, process reattachment or restart protocol.
- `KILL_ON_JOB_CLOSE` terminates Workers when the Supervisor dies; no restart/reattach protocol currently restores a safe live slot.
- A prepared drain cannot be abandoned or reissued after an unknown delivery/expiry without a signed fenced Worker `NOT_SEEN` result. Start-or-resume retry is not implemented.
- There is no separately approved soak-finalize operation, so a prior rollback slot remains protected.
- Candidate liveness is checked before transition evidence is committed, but liveness is not atomically fenced with the durable route-state commit. Production transitions stay disabled until that race is closed.
- The evidence log has no signed segment rotation or externally committed previous-segment head; its fixed file limit cannot prove the required 24-hour/scale run.
- Windows process recovery, filesystem/power-loss behavior, 100 real A/B switches, 24-hour soak, Zenno PID/start-time continuity and no-restart behavior are `NOT_RUN`.

## Candidate staging

1. Select the inactive slot and an immutable version directory.
2. Load the deployment-pinned RSA public keys from the read-only trust directory. The allowlist uses the DER SubjectPublicKeyInfo SHA-256 as key ID; verify the worker file digest and domain-separated RSA-PSS signature against the signed Release BOM.
3. Decode signed capability evidence with `CapabilityEvidenceCodec`, verify its RSA-PSS signature against a capability-only externally pinned trust store, and bind its attestation key separately from artifact, bridge-server, Supervisor-drain, Worker-drain and Journal keys. The signed statement and verification expectation must match the exact host, Release BOM, protected policy, worker artifact, version, slot, Zenno PID/start time, bridge server key, independent evidence-log count/head/file identity, connection continuity, switch count, soak duration, and bounded validity/freshness window. Expiry equality is expired. Until the Worker launch/runtime ABI exists, the derived assessment is `WAITING_EXTERNAL`; candidate authorization therefore cannot be issued.
4. Verify exact required capabilities and signed health evidence, then run shadow with zero device side effects and bind its digest to the artifact signature.
5. Call `BeginDrain`, then `PrepareDrainDirectiveAsync`. The Supervisor binds the complete active drain, scope, slot, artifacts, BOM, policy and routing epoch; asks the drain-domain-only signing broker for one RSA-PSS signature; verifies it against the deployment-pinned Supervisor public key; and persists the exact raw directive as PREPARED before returning it to transport. Concurrent/restart retry returns those same bytes. An expired wire is not re-signed under the same drain ID. Only an already durable PREPARED/COMMITTED Worker continuation may use the public continuation verifier, which retains canonical-wire, exact-expectation, key-ID and signature checks while skipping wall-clock freshness. If the Worker has no matching durable state after expiry, the drain remains blocked: safely abandoning it requires a signed, fenced Worker `NOT_SEEN` protocol that is not yet implemented.
6. Stop new intake on the old slot, drain and reconcile all in-flight commands, and receive the Worker-only raw `edge.worker.drain.receipt/v1` wire. The Supervisor verifies the pinned Worker signature and exact active expectation, derives the deterministic Journal request ID, then directly calls `IJournalDrainAttestationProvider` with a five-second bound. The separately signed rich Journal proof must bind that request ID, the same raw Worker wire SHA-256, canonical `WORKER_DRAINED` payload, owner receipt, scope, artifacts, BOM, policy, routing epoch, durability, and freshness. A stale exact Worker receipt is continuation evidence only and still requires this new fresh Journal proof. Supervisor, Worker, and Journal pinned key sets must be pairwise disjoint; Worker never receives the Journal signing key or rich owner proof.
7. Persist both raw proof digests and the checksum-chained route transition while holding the exclusive state-writer lease before exposing the new active slot, then route new commands by `device_binding_id`. Runtime startup uses `Resume`; a missing state file is never treated as a clean bootstrap. `DurableSupervisorStateStore` has no insecure fallback: composition must inject one `ISupervisorStateAnchor` authority bound to exactly one host and state-path identity. Its operations must be linearizable and crash-durable. Each change atomically compares the committed head, obtains an authority-generated unpredictable one-use preparation token for the exact next head, verifies that prepared snapshot, replaces the local file, and commits with the same token. After a crash, Resume commits only when the file equals that tokenized prepared head, aborts only when the file still equals the committed head, and rejects stale tokens and every third state. This is a recoverable two-resource protocol, not a cross-resource atomicity or directory-metadata durability claim. The repository memory anchor and Mac exception injection do not prove Windows power-loss behavior; production remains blocked until a Windows service/ACL, TPM, or equivalent implementation and filesystem fault testing are supplied and verified.
8. Keep the previous slot intact through soak. Staging cannot overwrite it; the current proposed runtime intentionally has no self-authorized soak-release path.

Supervisor-to-worker commands use `EdgeWorkerExchangeCodec`; signed drains use only `DrainDirectiveV1Codec`. Free-text `edge.worker.exchange/v1` DRAIN is forbidden. Worker receipts and health messages enter only through strict matching decoders. Receipt decoding also requires the exact source command and rejects any Soul, device, account, trace, idempotency, command, privacy, or request-hash mismatch. Command `request_sha256` binds 19 fields, including `occurred_at` and `privacy_class`. The codec validates the complete envelope, includes every nullable wire property, and rejects missing, duplicate, unknown, inconsistent, tampered, or oversized payloads. Receipts expose versioned `duplicate` and `retry_allowed` truth.

Supervisor-to-Zenno directives must use `BridgeDirectiveAuthenticator`. The fixed protocol is documented in `contracts/provided/edge.bridge.directive.v1.auth.json`: key IDs are SHA-256 over DER SubjectPublicKeyInfo and directive proofs are RSA PKCS#1 v1.5 SHA-256. This must not be changed to PSS merely because artifact and capability signatures use PSS. `edge.bridge.directive.v1.golden.json` is the cross-runtime public fixture.

## Rollback

Arm `kill_edge_command_intake`, stop candidate intake, call `BeginDrain` with the exact identity and trace scope, prepare and persist its one signed directive, reconcile, verify the Worker receipt and independently fetched Journal attestation, persist both proof digests with the route transition, then return to the previous exact validated slot. The logical route objective is five minutes. A missing previous digest, missing prepared directive, stale drain ID, untrusted Worker or Journal signature, wrong artifact/BOM/policy, non-durable Journal receipt, incomplete drain, half proof pair, missing state, or unknown outcome stops rollback completion.

## Windows-only acceptance

Set `DPS_EDGE_WINDOWS_GATE_CONFIG` to an absolute declarative configuration path, then provide the externally protected `DPS_EDGE_WINDOWS_GATE_CONFIG_SHA256`, `DPS_EDGE_RELEASE_BOM_SHA256`, `DPS_EDGE_PROTECTED_POLICY_SHA256`, `DPS_EDGE_WINDOWS_EVIDENCE_TRUST_STORE_FINGERPRINT`, and `DPS_EDGE_HOST_ID` process values before running `operations/windows-gate.sh`. The exact config bytes, trust store, BOM, policy and host must agree; the config additionally binds the worker artifact/version/slot, independent evidence-log root, and freshness limits. No implicit, empty, caller-selected, or repository-self-approved trust is accepted. `windows-gate.config.example.json` and `windows-host.config.example.json` document separate shapes and are not deployable.

Use `scripts/pwsh-pinned.sh` and `scripts/adb-pinned.sh` where Bash is available, or enforce their exact versions (PowerShell 7.6.2 and Android Platform Tools 37.0.0-14910828) in the Windows probe. Record the exact ZennoDroid version, .NET Framework, supported C# language level, CodeDom, GAC, DLL loading, ADB authorization, bridge ABI, loopback port, timeout, error semantics, SPKI-derived directive key ID, `RSA_PKCS1_SHA256` peer algorithm, ZennoDroid PID and start time, independent evidence-log root, and connection continuity. The gate also remains `WAITING_EXTERNAL` while `worker-launch-runtime-abi-unavailable` is present. Run one hundred real A/B switches and rollback checks, then a 24-hour soak only after that ABI blocker is removed in a separately reviewed change. No Mac or simulated result satisfies this gate.
