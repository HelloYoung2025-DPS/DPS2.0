# Consumed contracts

- `edge.worker.exchange/v1` is owned by `windows-edge-supervisor`. The worker consumes only `COMMAND` and produces `RECEIPT` and `HEALTH` instances without forking the schema. The owner-defined command hash uses the exact 19-field order and binds `occurred_at` plus `privacy_class`; nonzero timestamp offsets are rejected before hashing. `RECEIPT` repeats the original command request hash and carries non-null `duplicate` and `retry_allowed`; `HEALTH` carries `null` for those fields. The removed free-text `DRAIN` kind fails closed and cannot change intake state.
- `edge.worker.drain.directive/v1` is owned and signed by `windows-edge-supervisor`. A new drain begins only after the owner codec verifies exact canonical wire, every identity/deployment/policy/epoch expectation, bounded freshness, and the externally pinned Supervisor RSA-PSS identity. A durable PREPARED or COMMITTED continuation re-verifies the same canonical wire, expectation, key ID, and signature through the owner continuation API while intentionally not reopening the expired wall-clock window; that continuation cannot authorize a new drain.
- `edge.journal.append/v1` is owned by `edge-local-journal`; this module is an allowed producer for durable command lifecycle requests. The worker sends the complete owner DTO, emits `payload_json` in the owner's ordinal-property canonical form, and computes `payload_sha256` over the exact strict UTF-8 bytes of that canonical JSON. `command_id` and generated `entry_id` are restricted to the owner-defined ASCII token alphabet before crossing the boundary.
- `edge.journal.receipt/v1` is owned and produced by `edge-local-journal` after durable flush. The worker validates every scoped identity, entry field, timestamp, sequence, payload hash, chain checksum, and producer field before advancing a prepared command to `Completed`. Consumer-differential tests also bind the owner checksum profile (`edge.journal.checksum/v1`), including its domain separation, strict UTF-8, big-endian u32 length framing, field order, and journal-line discriminator; the worker does not invent a second checksum format.
- `edge.worker.drain.receipt/v1` is owned by `windows-edge-supervisor` and produced by this Worker only after signed authorization, stopped intake, reconciliation, and zero persisted/in-memory work. The Worker signs once, persists the exact UTF-8 wire as PREPARED, appends `WORKER_DRAINED` with `worker_receipt_wire_sha256`, validates the exact durable `edge.journal.receipt/v1`, then persists COMMITTED and returns the same raw wire plus deterministic Journal locator. Journal rich attestation is a separate owner wire requested directly by Supervisor; the Worker has no Journal attestation/admin capability or Journal key.

- `native.stop.proof/v1` remains byte-owned by `executor-gateway`, but this Worker consumes it only in `quarantine-only` mode. The old issuance class is a zero-authority tombstone: every call fails before runtime-identity read, native stop, signing, verification, or persistence. The bounded legacy store is internal and can return only quarantine metadata after decoding an already-existing artifact with the owner codec; it cannot create a proof or expose exact wire bytes. A v1 wire can never authorize `UNKNOWN_SUBMISSION`, become business success, or contribute positive compatibility evidence.

The proposed Policy-owned `native.stop.challenge/v1` and `native.stop.proof/v2`, the Release-BOM authority receipt, and the Supervisor route-assignment wire are deliberately not declared or copied here while their owner-facing Worker APIs remain unfrozen. Missing those exact opaque verified contexts is `WAITING_EXTERNAL` and leaves production intake disabled.

Unknown majors, kinds, properties, actions, steps, identities, leases, and states fail closed. Wire JSON is bounded, uses exact property names, and rejects duplicate or missing required properties before dispatch.
