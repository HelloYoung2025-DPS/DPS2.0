# Policy Approval tests

The 0.6.0 ownership tests assert that Policy Approval publishes no `native.stop.*` DTO or embedded resource, its contract project packs no native-stop Schema/Corpus, production factories expose no caller-selected trust, and `SubmitNativeOnceAsync` accepts only cancellation. The single public native-dispatch Integration case must return `WAITING_EXTERNAL` and create zero PENDING rows. Native result truth remains `CONFIRMED_SUCCESS`, `FAILED`, or `UNKNOWN_OUTCOME`; transport acknowledgement is not success.

Unit and Contract suites cover strict opaque identifiers, strict canonical commitments, delimiter-collision resistance, invalid UTF-8, deterministic deny/approve rules, immutable proposal snapshots, independent promotion signer separation and exact binding, signature and role attacks, unknown policies, exact scope, kill switch, rate budget, platform authorization, two-second execution-fence DTOs, non-constructible authoritative snapshots, and the policy-owned native-submission lifecycle. Decision, promotion, fence, intent, acknowledgement, reconciliation, recovery, and state owner corpora are checked by Draft 2020-12 schema tests and by their C# DTO validation, including unknown, missing, duplicate, UUID, canonical-time, year-zero, Int64, digest, signature, authority, lifetime, predecessor, evidence, Release BOM generation, and cross-field rejection cases. Both gates lock the exact expected case ID sets, counts, and uniqueness so removing an adversarial case is a failure.

The composition API-shape tests reflect the public clients and options. They fail if executor regains reconciliation/recovery methods, if reconciler/recovery gains acquire/begin/acknowledgement methods, if one options record regains another PostgreSQL credential, or if any of the eight evaluation/promotion/revocation/fence/executor/reconciliation/recovery/state authority fingerprints collide. Credential `ToString()` output must remain redacted.

The required Integration suite uses only a real PostgreSQL 18.4 instance supplied through `DPS_TEST_POSTGRES`. It covers concurrent same-request idempotency, a one-connection pool proof for transaction-bound state reads, atomic one-unit rate-budget competition, different-hash quarantine, transaction crash windows, restart readback, exact cross-Soul/device/account isolation, independently signed promotion and signed revocation, stale revisions, final database-clock revalidation, execution-fence lock serialization, status-reason and exact outbox-to-receipt constraints, prompt-injection-shaped parameters, kill switch/rate/platform authorization, revoked runtime state, exact least-privilege runtime-role identity/attributes, and owner-level append-only triggers.

The lifecycle portion proves three separate native-submission crash windows: pending committed before any native call, native submission flushed before acknowledgement commit, and acknowledgement validated before the policy transition commits. It also proves that an exact duplicate begin is readback-only, pending survives restart and blocks redelivery, a second acquire waits behind the shared command lock and then rejects committed pending, concurrent acknowledgement/reconciliation commits exactly one terminal branch, lock waits cannot extend a fence or receipt, a durable acknowledgement is terminal, cross-scope/forged reconciliation and recovery reuse fail, and only `CONFIRMED_NOT_SUBMITTED` plus a distinct human recovery authority can bind the next attempt.

The former eight label-only missing-authority callback cases are deleted and are not accepted as Integration evidence. The required real PostgreSQL 18.4 suite now inspects both dormant ledger tables, all four UPDATE/DELETE/TRUNCATE triggers, all three function ACLs, and actual denial for generic runtime, executor, reconciler, and recovery roles. It also seeds both tables as the owner and proves UPDATE, DELETE, and TRUNCATE are rejected. Missing or unreachable PostgreSQL is `INFRA_ERROR`, never a skip or Mock success. The functions remain ungranted and unusable after the test.

Attempt 2/3 acquire must also reject an admin-forged recovery chain whose table columns look exact but whose stored reconciliation/recovery envelope, policy state, digest, signature, predecessor, or fresh next-intent binding is invalid. That negative case requires real PostgreSQL owner setup and cannot be replaced by a Mock.

The database gate creates pairwise-distinct generic-runtime, executor, reconciler, and recovery login roles. It proves disjoint security-definer grants, no role membership or direct table mutation, exact JSON field sets, missing/unknown-field RPC rejection, removal of the legacy five-argument begin overload and generic helper, and unknown-overload detection. Missing PostgreSQL is `INFRA_ERROR`, never a skip or Mock success; the suite refuses port `55434` and `dps_gbrain_company`.
